# Релизы и автообновление

Это руководство для мейнтейнера. Оно объясняет, как публиковать релиз, чтобы у
пользователей была стабильная постоянная ссылка на скачивание, которая заодно
питает встроенную проверку обновлений.

## 1. Именование

Alter использует версии на основе даты: `ГГГГ.ММ.ДД` с номером сборки.

- **Тег:** `v2026.07.24`
- **Заголовок релиза:** `Alter 2026.07.24 (build 10)`
- **Имя APK-ассета:** держите его **ровно** `Alter.apk` в каждом релизе, поскольку от этого
  имени зависит постоянная ссылка ниже, оно не должно меняться.

## 2. Публикация релиза

1. Перейдите в **Releases → Draft a new release**.
2. **Choose a tag** → введите новый тег (например, `v2026.07.24`) → *Create new tag
   on publish*.
3. Задайте **заголовок** и вставьте заметки (используйте `.github/RELEASE_TEMPLATE.md`).
4. **Прикрепите** сборку `Alter.apk` как бинарный ассет.
5. Оставьте включённой галочку **«Set as the latest release»**.
6. **Опубликуйте релиз.**

> Бинарники живут в Releases, а не в дереве репозитория. Не коммитьте APK в репо.

## 3. Постоянная ссылка на скачивание

Поскольку ассет всегда называется `Alter.apk`, а релиз помечен как последний, этот
URL всегда ведёт к свежему APK:

```
https://github.com/Ivanparfenchuk/Alter/releases/latest/download/Alter.apk
```

Используйте его для кнопки на сайте, в Telegram и для действия «Скачать обновление»
внутри приложения.

## 4. Проверка обновлений в приложении

Чтобы проверять обновления изнутри приложения, читайте GitHub Releases API и
сравнивайте тег с установленной версией:

```
GET https://api.github.com/repos/Ivanparfenchuk/Alter/releases/latest
```

Полезные поля в JSON-ответе:

- `tag_name`: последняя версия (например, `v2026.07.24`). Сравните с установленной,
  чтобы решить, показывать ли предложение обновиться.
- `body`: заметки к релизу для показа в диалоге обновления.
- `assets[].browser_download_url`: прямой URL для скачивания прикреплённого APK
  (эквивалент постоянной ссылки выше).

Предлагаемый сценарий:

1. Сделать `GET` к эндпоинту выше.
2. Если `tag_name` новее установленной версии, показать предложение обновиться, а в
   качестве чейнджлога использовать `body`.
3. По подтверждению скачать по постоянной ссылке `releases/latest/download/Alter.apk`
   и запустить установщик.

> Неавторизованный GitHub API имеет ограничение по числу запросов в час на один IP.
> Проверяйте при запуске приложения или по требованию, а не частым опросом.
